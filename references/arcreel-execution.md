# ArcReel 执行适配

只在当前任务实际使用 ArcReel 时读取。本文件连接制作质量关口与工具操作，不替代当前 MCP schema、运行中服务或官方 `video-workflow` Skill。技术事实、枚举、模型能力、价格和生成时长均在执行时重新核对。

## 接手与范围

1. 显式确定项目；用户已指定集数时才限定该集。开始或继续项目前读取 `get_workflow_plan`，对照本轮授权、已通过的质量关口、在途任务和预算预留。
2. 仅查状态或复盘时只读。项目推进只执行当前 `next_action` 中处于授权范围内的动作，之后刷新计划；技术计划不代表故事、质量或支出已获批准。
3. `next_action` 越过集数、修改范围或预算时报告冲突。`type=none` 时报告结构化阻断；导出路径以当前官方 Skill 和用户所选宿主为准。

## 方舟文字生成与主编审改

1. 工作流计划指向文本生成时，先用当前批准方向、Series Bible、续集上下文包和本集叙事契约组织任务；方舟语言模型产出候选文字，Agent 承担总编剧审改和跨阶段制作判断。
2. 生成后读取实际正文及 canonical revision，逐项检查人物动机、因果、七条硬约束、跨集连续性、分镜的画面与声音可执行性。保留合格部分，直接修订有问题的段落，或给模型具体修改目标后再复核；不把任务 `succeeded` 当作剧本通过。
3. 生成稿即使已落入 ArcReel 正式文档，也要区分“已存储”和“内容已采用”。在本轮授权内，使用当前支持的草稿或事务补丁接口提交审改版，回读 revision 与正文；通过 G1 内容审查后再放行依赖该文本的制作步骤。

## 写入与引用

- 正式数据通过受支持的 MCP/REST 事务接口修改，不直接编辑数据库或项目文件。改剧本前读 canonical revision，提交后回读验证。
- Series Bible、资产变体、续集上下文包和分集叙事契约只作派生生产视图，均记录来源 revision。创建新集或改剧本时，把通过审查的变化转成当前接口支持的补丁；本地 JSON 不覆盖正式项目数据。
- G1 完成叙事契约后再提交剧本补丁；G2 用完整粗片核算前 3 秒冲突、爆点间隔、六个话语落点、静默上限、后 1/3 反转和“压→爆”。这些属于内容准入，与 `next_action` 的技术可执行状态分开。
- 角色、场景、道具及分镜引用逐项核对；场景不能只写在自然语言提示词里而漏掉对应结构化字段。外部素材按真实来源、目标 ID、版本及采用状态登记，默认模型标签不证明生成来源。
- 提交前预览实际 prompt 或使用当前可用的 dry-run；附加指令只补当前镜头的缺口，避免长篇历史模板与内置提示相冲突。描述修正不等于旧图片或视频已经修好。
- 重生成已有产物时显式指定目标，并先检查依赖影响与费用授权；`stale` 不自动意味着应覆盖。

## 生成、恢复与费用

- 计费前读取当前能力与价格，核对模型、输入形式、音频策略、时长/分辨率、目标数量及预算余额；先验收覆盖主要风险的小样。
- 提交后保存任务或批次 ID，按工具返回的轮询间隔与上限查询。供应商已提交或扣费不明时先续查原任务，不直接重试。
- 区分工作流步骤、任务状态、供应商提交/计费状态、产物技术状态，以及实际画面/声音的内容验收。`succeeded/current` 不代表镜头可采用。
- 当前工具若对整批设置准入限制，先满足该限制，不拆批绕过；不受影响、仍在授权内的独立准备工作可继续。

## 交付同步

服务器项目/剧本修订、本地采用素材、声音文件、剪辑时间线和交付片保持映射。外部制作与本地剪辑可以采用，但要登记真实来源、上传/回写状态和当前批准版本；本地成片完成不自动代表 ArcReel 状态已同步。验收、交付和公开发布分别取得对应确认。
