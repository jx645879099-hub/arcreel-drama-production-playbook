# 阶段准入与验收

本文件是每次制作操作的执行检查，不取代 G0–G4。G 是作品质量里程碑；下表是每种产物的提交前/采用前检查。即使用户只要人物图、不做整片，也执行资产这一行；不凭空要求先制作整集成片。

## 1. 记录与停止规则

复制 [阶段检查模板](../assets/templates/阶段检查记录.json)，分别填写 `prepare`（提交前）和 `accept`（采用前），保存在项目生产资料中。续做先读已有记录，单次操作可覆盖同一阶段的一批目标，避免逐格向用户提问。模板及脚本均为本地生产资料，不是 ArcReel 接口格式。

- `targets` 精确列出本次目标 ID；范围排除项沿用用户指令，如“除分镜图之外”。
- `source_revision` 和 `dependencies` 引用正式文本及采用基线版本。另从当前工具读取项目/集数、revision、依赖版本和采用状态，保存为 `--current` 快照；不得从检查记录复制期望值冒充当前状态。
- 不使用 ArcReel 时，记录实际本地采用稿版本/文件哈希，不伪造服务器 revision。全新剧本尚无稿件时，仅 `script/prepare` 允许记录与最新快照都显式填 `source_revision: null`，并在 source_alignment 说明；采用前须产生实际可追溯版本。自由讨论/只读分析不要求为了填表先创建服务器项目。
- 每个检查含 `status`、`evidence`、`findings`。证据登记 `id/uri/version/kind`，指向实际正文、配置、提示词、原图、审片记录等；本地路径相对检查 JSON 所在目录解析。远程链接应绑定不可混淆的素材 ID/版本，禁止仅引用可变的项目首页。
- `findings` 写观察事实，例如“已对照 C01/C02/C03 原图，线条、皮肤材质与头身比例一致；C02 没有额外头像”，不写“已检查”占位。工具返回日志可证明提交成功，不可证明画面合格。
- `accept.results` 对每个目标记录实际产物、版本、检查结论；所有目标均通过才整批放行。部分失败时拆出通过的独立子批并保留原失败记录，依赖失败目标的镜头继续停止。
- 必需检查不支持用 `N/A` 跳过。某个子项确实不适用，在 findings 中说明具体原因和仍检查了什么；不把“无权限预览”写成不适用。
- 缺证据、版本过期、未看实际产物、关键设置未落实、内容失败、授权不足：暂停受影响动作。可以修文本、整理提示词及准备独立任务；不盲目重试收费生成。
- 延续已有授权，不重复问用户确认日常修订。费用批准需覆盖返工次数/上限；用尽、未知计费未核清或路线实质变化时停止新增提交。

运行：`python scripts/validate_production_gate.py CHECK.json --current CURRENT.json`。当前快照结构：

```json
{"project":"实际项目ID","episode":"实际集数或项目级范围","source_revision":"当前正式版本","dependencies":{"visual_contract":{"version":"style-v1","adoption":"accepted"}}}
```

校验器确定性检查必需记录、证据引用、本地文件存在、版本匹配、逐目标覆盖和已报告阻断；不判断图像美学、不读取远端内容、不认证审批真实性，也不自动拦截 ArcReel。Agent 必须实际执行内容审查并在调用前运行检查，不得用脚本 PASS 替代审查。

证据项格式为 `{"id":"C01-image","uri":"素材原图路径或版本化URL","version":"asset-v2","kind":"image"}`，kind 可为 text/image/audio/video/record/prompt。检查项格式为 `{"status":"pass","evidence":["C01-image"],"findings":"实际观察和对照结果"}`，未完成用 pending，失败用 fail。采用记录每个 results 项为 `{"target":"C01","version":"asset-v2","artifact":"C01-image","inspection":{"status":"pass","evidence":["C01-image"],"findings":"实际逐图发现"}}`；这些是结构示例，不是验收证据。prepare 的 checks 必须替换为本阶段项，accept 另建记录保留原 prepare。

## 2. 按阶段读取这一行

所有 `prepare` 必查：`scope_authority`（目标及费用范围）、`source_alignment`（实际正文和引用版本）、`execution_config`（实际模型/路由、规格、供应商能力与本次调用参数，不记录密钥；纯本地编辑写明无需供应商调用）。所有 `accept` 必查：`source_alignment`、`actual_review`（检查方式、范围及产物证据）。表中标识符写入 checks。

| stage | prepare 额外必查 | accept 额外必查；验收内容 |
|---|---|---|
| `script` | `story_brief`：已批方向、连续性上下文、七条契约 | `story_contract`、`continuity`：读取完整模型稿，主编审改，核对动机、因果、伏笔、实际揭示时刻与所有台词；回读采用正文 |
| `assets` | `visual_contract`、`prompt_scope`、`reference_binding`、`sample_gate`：具体共同风格、提示词作用域、真实引用及代表样本策略 | `identity_state`、`style_consistency`：每张原图的身份/形态/服装/道具/额外元素；跨人物、场景、道具并排核对画风，不以同模型代替 |
| `storyboards` | `visual_contract`、`prompt_scope`、`reference_binding`、`shot_plan`：采用资产版本、单镜画面任务、声音与前后状态 | `identity_state`、`style_consistency`、`spatial_continuity`、`shot_coverage`：逐张看构图/人物/状态；按故事顺序检查景别、视线、轴线、空间尺度、道具归属、动作入出点及遗漏镜头 |
| `roughcut` | `shot_plan`、`sound_plan`：完整镜头与临时声音时间线，标记占位 | `story_contract`、`timing_sound`、`spatial_continuity`：完整播放并试听，不拿 JSON 时间表当已看粗片；核对最终时长及七条契约 |
| `audio` | `sound_plan`、`voice_binding`：完整台词 ID、说话者/声线、情绪/语速与时长预算 | `voice_binding`、`timing_sound`：逐条试听错字/漏字/身份/音色/表演，整轨听接点、响度及覆盖；口型适用时复核 |
| `video` | `reference_binding`、`shot_plan`、`sample_gate`、`roughcut_gate`：已采用分镜、动作链、运镜/音频策略、G2证据与风险小样 | `identity_state`、`spatial_continuity`、`motion_quality`、`timing_sound`：看完整片段及相邻接点，不只看封面；核对变形/闪烁/动作结果/时长/声音 |
| `delivery` | `adoption_map`、`export_spec`：时间线只使用采用版本，规格与本轮交付一致 | `story_contract`、`timing_sound`、`spatial_continuity`、`export_spec`：实际播放最终导出全片，复核字幕/片尾/声画/规格和七条契约；用户最终接受另记 |

`reference_binding` 同时检查支持的参考图输入、实际资产 ID/版本/可访问性；无需参考图的探针要写明“无参考图试样”，不冒充锁定身份。`sample_gate` 在独立技术探针时注明最小目标、风险、停止条件与授权；扩大批次必须引用同配方已采用的代表样本。视频早期探针的 `roughcut_gate` 可记录“G2前的独立技术探针”，但不是正式成片镜头放行；正式批量视频必须有 G2 证据。

## 3. 视觉契约与提示词作用域

### 先锁定项目意图，不锁死某一种画风

风格契约至少包含：版本、用户已选/已批方向来源、媒介（如二维或三维）、造型比例与面部语言、轮廓/线条、材质与明暗、光照/色彩处理、排除项、实际视觉锚点及适用范围。已有明确选择就继承，禁止因当前案例擅自给所有项目加“三维CG/三视图”。确实缺少决定性画风选择时，只问该选择；不是把每张图的质量检查交回用户。

资产、分镜、视频检查记录中，`visual_contract` 必填 `version/medium/shape_language/line_and_material/light_and_color/exclude/decision_evidence`，具体定义见模板；decision_evidence 引用方向来源记录。`dependencies.visual_contract` 必须等于该版本，并与最新事实快照中的采用基线匹配。此结构用于拦住空风格字段，实际是否兑现仍看图/看视频。原系统没有风格字段时，这份本地基线也不假称已写回服务器。

文字风格未经过成图验证时，先生成并实际检查最小代表样本，采用后作为可追溯锚点；接着验证明显不同类别的组合，再扩批。支持参考图时传真实素材；仅文本控制时明确限制，先验证组合再放量。一个角色合格不能证明所有角色一致，人物一致也不能证明场景材质一致。

### 拼装层次，不混进永久描述

`项目视觉契约 + 主体稳定设定 + 当前变体状态 + 本阶段输出要求 + 本镜动作/空间/声音 + 适用排除项`。

- 项目契约控制共同渲染语言；统一风格不等于统一衣服、光线方向或场景。
- 主体设定只放身份/稳定外观；服装、伤势、变身进入有生效范围的变体。
- 白底、三视图、单人设定表只属于资产任务；不得流入叙事分镜，让战斗镜头变成白底站姿。
- “伪装圣女”和“魔女真身”分别明确使用范围；基准图不拼入额外头像或提前泄露真身。例子仅说明状态隔离，不限定其他项目角色。
- 分镜只描述本镜看得见的初始状态、关键动作、动作结果、位置/方向/持物及摄影目的。一个镜头承载过多状态变化就拆镜；画面提示与台词/音效分栏，不用抽象情绪词替代可见事件。
- 检查最终拼装结果中的相互冲突、被内置模板覆盖的约束、缺失的结构化场景引用及无效参考图。API无预览能力时按[执行适配](arcreel-execution.md)降级验证，不声称看过完整 prompt。

## 4. 版本传播与恢复

维护依赖映射：`剧本/视觉契约 → 资产/状态变体 → 分镜 → 动态粗片/视频/声音 → 时间线 → 导出`。粗片可以使用明确的临时占位，与正式素材采用分开。

- 风格改变：相关资产、分镜、视频审查过期；先评估保留/重做，不直接全量重生成。
- 主体或变体改变：只反查引用它的镜头；新图不能悄悄替换已经验过的旧引用。
- 台词/镜头时长/顺序改变：重算全长、反转阈值、爆点和静默，重审相关声音/接点，最终全片再看。
- 提示词/模型/参考图组合改变：已有小样不自动覆盖新配方。
- 断网恢复：先查原任务及扣费；回读 current 版本与实际采用素材再继续。`current` 仅是技术字段，不是采用证明。

## 5. 防止“填表通过”的真实检查

- 不以计划中的反转标签计时；按观众第一次确实获知关键改变的时刻计算，提前台词泄底也算。后面的变身特效不能把实际反转推迟。
- 台词清单与实际全文逐句对齐；不得只抄够六句。计划声音、已合成声音、实际混音分别记录；`silence_segments: []` 没有完整声轨覆盖证据时仅为待验证假设。
- 63秒版本不能继续引用60秒旧时间轴的验收。校验器通过的是输入声明，不是声明本身真实。
- 看原图及组图、看完整视频及接点、听实际音轨；只读任务日志/提示词/缩略图不能完成对应内容验收。访问失败如实记待验。
